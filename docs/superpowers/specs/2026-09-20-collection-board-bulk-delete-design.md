# 收集板内容批量删除设计

**日期：** 2026-09-20
**状态：** 已获用户确认，待用户复核
**范围：** 新标签页收集板、普通网页侧栏收集板及两端共享存储同步

## 背景

当前收集板支持搜索、类型筛选、拖动整理、手动添加和单项删除，但没有适合清理多项内容的选择模式。新标签页和网页侧栏分别渲染同一份 `sidebar` 数据：新标签页使用 `js/app.js`，网页侧栏使用 `js/content.js`，公共数据规则位于 `js/collection-board-core.js`。

快捷方式区域已经有“批量管理”交互，可作为收集板批量操作的视觉和交互参考。收集板卡片还承担打开链接和拖动定位职责，因此批量模式必须暂时隔离这些行为，避免点击选择时误打开或移动卡片。

## 目标

1. 在新标签页和普通网页侧栏都提供一致的批量管理入口。
2. 支持按稳定内容 `id` 逐项选择，并支持全选当前搜索/类型筛选结果。
3. 删除前明确显示数量并二次确认。
4. 删除后短时间内可以恢复被删除内容及其完整数据。
5. 删除和撤销通过现有共享存储同步到另一端，不覆盖期间其他页面新增或编辑的内容。
6. 渲染更新继续保持当前滚动位置和玻璃卡片拖动体验。

## 交互设计

### 批量模式

新标签页和网页侧栏的收集板标题区域各增加“批量管理”入口。进入批量模式后：

- 卡片点击只负责切换选中状态，不打开链接；
- 暂停卡片拖动和编辑入口，避免与选择操作冲突；
- 显示“全选当前筛选”和“清空选择”；
- 显示实时已选数量；
- `Enter` / `Space` 切换当前卡片的选中状态，`Escape` 退出批量模式；
- 控件使用 `aria-label`、`aria-pressed` 或 `aria-selected` 表达状态。

选择状态只保存在当前页面会话中，不写入收藏数据。选择集合按内容 `id` 保存，不使用数组下标。

搜索或类型筛选变化时保留仍然存在的已选 `id`，因此用户可以跨筛选条件累计选择。“全选当前筛选”只补选当前可见内容；“清空选择”清除整个当前页面的选择集合。

### 删除与撤销

“删除所选”在没有选中项时不可用。点击后显示确认信息，例如“确定删除已选中的 3 项收集内容？”。确认后在一次数据操作中移除所有选中项，并清理当前页面的选择状态。

删除完成后显示约 8 秒的“撤销”操作。撤销快照只保存在内存中，刷新页面或重启浏览器后不再提供这次撤销。新的删除操作会替换旧的撤销快照。

撤销恢复被删除项的完整对象，包括类型、标题、网址/图片地址、文字、标签、`x`、`y` 和 `z`。恢复按原始数组位置插入；如果对应 `id` 已经存在，则跳过该项，避免覆盖期间的其他修改。

## 架构与数据流

### 公共数据助手

在 `js/collection-board-core.js` 增加无副作用的批量操作助手：

- 按 `id` 移除一批内容，并返回剩余内容及带原始位置的被移除项；
- 按原始位置恢复内容；
- 对重复恢复和已经不存在的 `id` 保持幂等。

这些函数不负责 DOM、提示框或存储，便于新标签页、网页侧栏和 Node 测试共同使用。

### 新标签页

在 `js/app.js` 的收集板状态中增加临时的批量模式、选中 `id` 集合和撤销快照。`renderSidebar()` 根据批量状态渲染选中样式和交互，并继续在重绘前后使用现有滚动捕获/恢复逻辑。

删除时从当前 `S.sidebar` 计算选中项，调用公共助手生成删除结果和撤销快照，通过现有 `store.save({ sidebar: ... })` 保存，再重绘收集板并显示撤销操作。

### 网页侧栏

在 `js/content.js` 的 Shadow DOM 模板中增加与新标签页对应的批量控件、计数和选中样式。批量选择时屏蔽现有卡片打开、拖动和单项删除事件；删除仍通过现有 `saveSidebar()` 保存共享 `sidebar`。

### 跨页面同步

两端继续使用 `lg.newtab` 中的 `sidebar` 字段，不新增数据格式或独立数据库。补齐新标签页对 `chrome.storage.local` 侧栏变化的监听，并保留网页侧栏已有监听：

1. 收到存储事件后规范化并比较侧栏内容；
2. 内容没有变化时只更新数量，避免不必要的完整重绘；
3. 内容变化时更新本地侧栏、清理已经不存在的选中 `id`，再捕获滚动位置并重绘；
4. 撤销通过最新侧栏数据做按 `id` 合并，不覆盖删除窗口内另一端的新增或编辑。

直接打开 HTML 的 `localStorage` 预览模式继续支持同一套批量逻辑，但不承诺跨浏览器页面同步。

## 边界与错误处理

- 当前筛选没有结果时，“全选当前筛选”不可用。
- 没有选中内容时，删除按钮不可用，并提示“请先选择收集项”。
- 确认框使用实际选中数量，不根据当前可见数量猜测。
- 存储事件带来的内容变化会清理失效选择，避免删除不存在的对象。
- 撤销只补回当前不存在的 `id`，不覆盖期间其他内容。
- 不改变现有 200 项侧栏上限、图片持久化、重复链接检测、拖动定位和导入/导出格式。

## 验证方案

### 公共逻辑测试

- 批量移除只删除指定 `id`，保留其他对象和原顺序；
- 移除结果包含每个对象的原始位置；
- 恢复保留对象的全部字段；
- 重复恢复不产生重复项，也不覆盖已经存在的 `id`；
- 搜索/类型筛选和选择集合按 `id` 工作。

### 表面与存储测试

- 新标签页和网页侧栏都存在批量入口、全选、清空选择、删除和撤销反馈；
- 批量模式下卡片不打开链接、不拖动、不触发普通单项操作；
- 新标签页删除后网页侧栏同步更新，网页侧栏删除后新标签页同步更新；
- 同步重绘不会丢失滚动位置；
- 删除确认、空选择、空筛选和撤销路径均有覆盖。

### 实际 Edge 扩展验收

在临时 Edge 扩展环境中使用测试收集项验证：

1. 两端进入和退出批量模式；
2. 单项选择、取消选择和全选当前筛选；
3. 删除确认后两端同步消失；
4. 撤销恢复原卡片、位置、标签和层级；
5. 搜索、类型筛选和滚动位置在批量操作前后保持正确；
6. 批量模式不会误打开链接或移动玻璃卡片；
7. 现有测试、语法检查和 `git diff --check` 通过。

## 非目标

- 不增加永久的回收站或跨重启撤销历史。
- 不做批量编辑标题、标签或类型。
- 不改变收集板卡片布局、玻璃效果、拖动算法或存储字段格式。
- 不将网页侧栏的批量选择状态同步给另一端；只同步实际的收藏数据变化。
- 不处理与本功能无关的现有未提交工作区改动。
